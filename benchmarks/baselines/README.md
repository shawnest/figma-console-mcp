# Benchmark baselines

The JSON files in this directory are deliberately promoted, reviewable reference results. They are not regenerated by `npm test`, `npm run benchmark`, or CI smoke runs.

The committed baselines keep the result envelope, environment/configuration metadata, scenario metrics, and raw samples from the deliberately promoted run. Full timestamped runs under `benchmarks/results/` are ignored by Git. Keep a full raw result externally when a pull request needs an audit trail; record its path or artifact URL in the pull request. If future fixture growth makes the committed files material in size, replace them with compact summaries and retain the raw-results policy here.

To update a baseline:

1. Build and run the relevant benchmark with the documented default fixture and latency settings.
2. Compare the candidate result with the current baseline.
3. Review the Markdown report and correctness/lifecycle checks.
4. Promote the deliberately selected result with the benchmark's `--promote` option.
5. Commit the baseline change separately from the performance optimization when possible.

Comparisons are meaningful only when the before and after results use the same fixture version, critical configuration, and machine environment. The comparator refuses percentage changes when those inputs differ.
